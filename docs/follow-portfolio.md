# 跟單配置

入口 `follow.html`，四個原有頁面導覽互通。使用原有 Firebase modular SDK 12.14.0 與 fbReady；不更動初始化、驗證規則或 main 排程。

## 資料

`users/me/followPortfolios/default` 保存設定、完整朋友快照、實際持股、現金、快照歷史與成交。單一 transaction 以 revision 比對避免跨裝置覆寫；連線錯誤後必須重新載入確認，不自動改成本機儲存。此帳本沿用既有單人 users/me 匿名登入模型，並非每個 UID 獨立帳戶。

朋友原始庫存不可硬編碼到公開原始碼；初始 JSON 透過使用者匯入。所有数量均為「股」。朋友舊成本未知，不計算朋友損益。自己的未知成本用 null，不用參考價代替。

跟單帳本與 stocks/、realizedPnl/ 獨立；不在200萬計畫重複加總。只有明確記錄的實際成交會影響此帳本股數、現金與成本。盤點校正不改寫過去成交。

## 計算

1. 完整快照每檔股數 × 快照參考價計算朋友市值分母；嚴格 > 門檻入選。
2. 原占比模式保留剔除部位的現金；配滿模式依入選市值重新正規化。
3. 預算包含已投入部位。先扣可調費用預留，再按權重分配，以 floor 取整股；剩餘現金保留。
4. 報價可更新目標股數，但不重寫朋友占比或推測朋友交易。缺報價且無快照價格時，該行阻擋計算；歷史快照價格明示日期和來源。
5. 低於門檻／消失的我的舊持股列為退出。小額暫緩不套用完全退出或首次建倉。
6. 實际庫存需先盤點確認；成交須明確確認，檢查現金和可賣股數。買入費用計入成本，賣出扣實付費稅，成本未知則不顯示已實現損益。

`scripts/fetch_stocks.py` 於既有 stocks.yml 執行時讀取跟單帳本代號並抓價。不增加排程，不傳送 LINE。通知為更新後頁內調整清單；使用者手動輸入朋友通知或匯入快照。

## 測試

`node --test tests/follow-core.test.cjs`。純計算測試不讀寫正式 Firebase。瀏覽器使用假資料層測試匯入、盤點、成交、渲染與手機寬度；真正 Firebase 跨装置寫入需使用者首次匯入確認。

## 匯入

JSON: `{ "date":"YYYY-MM-DD", "items":[{"symbol":"1234","name":"股票名稱","market":"TW","shares":1000,"price":100}] }`。

或 CSV 每行 `代號,名稱,TW或TWO,股數,參考價`（數字不可含千分位）。匯入先載入草稿，核對日期／數量後儲存。保留最近50份快照、100筆更新事件、最多500筆成交，超限阻擋新增成交而不靜默刪除。備份輸出包括帳本及未存朋友草稿；還原恢復已儲存帳本，draft 欄位可另行匯入。
